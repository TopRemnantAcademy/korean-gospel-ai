# Code Review 检查清单（评审人侧）

> 目的：把"资深开发凭直觉挑出的问题"变成团队可复用的固定检查项。
> 每条都对应本项目真实踩过的坑。评审时**逐条过**，不符合就打回。

## 1. API 契约与类型（对应 A2: response_model 不匹配 → 永远 500）
- [ ] 每个路由的 `response_model` 与实际返回结构**完全一致**（字段名、类型、嵌套）。
- [ ] Pydantic 模型变更是否破坏前端/移动端契约？是否需版本化？
- [ ] 错误响应走统一 `HTTPException` / 错误封装，不裸 `return {"error": ...}`。

## 2. 流式输出与异步（对应 A1: SSE 换行转义错误）
- [ ] SSE / `StreamingResponse` 中 `\n` 正确转义，心跳包不丢。
- [ ] 异步函数无阻塞调用（不在 `async def` 里跑同步重 IO）；`await` 没漏。
- [ ] 并发资源（Qdrant embedded）确认**单进程占用**，不与 ingest 同时跑。

## 3. 安全与合规（PIPL / SSRF / 钱包 / 多租户）
- [ ] 生物识别相关：PIPL 授权流程完整，未授权不采集。
- [ ] 自定义域名 / 外部 URL 接入：走 SSRF 防护（白名单 + 内网拦截）。
- [ ] 积分/额度（credit-lot）操作满足**钱包不变量**，无负数/超额。
- [ ] 多租户：`WORKSPACE_SCOPED_MODELS` 隔离生效，无越权读取。

## 4. 数据层与迁移（对应 A3: Alembic 重复列 drift）
- [ ] **禁止手改迁移文件**；新增列/表走 `alembic revision --autogenerate` 单一来源。
- [ ] 迁移可前向+后向执行，不在迁移里写破坏性数据操作。
- [ ] RAG 写入路径（dense vec + BM25）确认不破坏索引契约。

## 5. 可观测性与性能
- [ ] 新增外部调用（LLM ~78s 推理）有超时、重试、降级；前端有 loading/thinking 态。
- [ ] 日志含 request_id / workspace 上下文，便于定位。
- [ ] 新增依赖是否显著增大包体 / 拖慢启动？

## 6. 测试与质量门禁
- [ ] 关键路径（API 契约、RAG 检索、并发锁）有测试。
- [ ] `ruff` / `mypy` / 安全扫描在本 PR 无新增阻断项。
- [ ] 不降低现有覆盖率（后续会设门禁阈值）。
