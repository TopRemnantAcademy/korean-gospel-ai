# 중한 콘텐츠 번역 시스템 — 필요성 3차 재평가

> **이전 분석**:
> - v1 (`evaluation-dual-lang-storage.md`): 전체 콘텐츠 KO+ZH 저장 → ❌ 불필요
> - v2 (`design-term-translation-system.md`): 용어집 기반 번역 통제 → ❌ 사용자 피드백: 보편적 성경 용어는 번역 대상 아님
> - **v3 (본 문서)**: 시스템 자체가 필요한지, 필요하다면 무엇을 해결해야 하는지 처음부터 다시 검토

---

## 1. 전제 해체: 지금까지 무엇을 잘못 가정했는가

### 잘못된 가정 #1: "번역이 부정확할 것이다"

| 가정 | 실제 |
|------|------|
| LLM이 `보혈`을 `血`로 오역한다 | 최신 LLM은 맥락을 이해한다. 문장 단위로 번역하면 거의 오역하지 않는다. |
| LLM이 신학 용어를 모른다 | GPT-4, Claude 수준 LLM은 기독교 신학 용어를 한국어↔중국어 양방향으로 정확히 안다. |
| 용어집으로 통제해야 한다 | 보편적 성경 용어는 통제 대상이 아니다. 중국 기독교인도 한국 기독교인도 같은 개념을 쓴다. |

### 잘못된 가정 #2: "저장된 번역이 실시간 번역보다 낫다"

번역 품질은 저장 여부가 아니라 **번역을 수행하는 모델의 품질**에 달려 있다. 저장해도 결국 LLM이 번역한 결과를 저장하는 것일 뿐이다. 품질 차이는 없다.

### 잘못된 가정 #3: "중국어 사용자를 위한 무언가가 필요하다"

| 실제 질문 | 답변 |
|-----------|------|
| 중국어 사용자가 있는가? | **모른다** — 데이터 없음 |
| 몇 명인가? | **모른다** |
| 그들이 번역 품질에 불만이 있는가? | **모른다** — 피드백 채널 없음 |
| 기존 `target_lang="zh"`로 충분하지 않은가? | **검증된 바 없다** |

→ **해결해야 할 문제가 실재하는지조차 확인되지 않았다.**

---

## 2. 냉정한 분류: 무엇이 번역 대상이고 무엇이 아닌가

### 번역이 필요 없는 것 (LLM이 이미 완벽하게 처리)

| 유형 | 예시 | 이유 |
|------|------|------|
| 보편적 성경 인물/지명 | 예수→耶稣, 예루살렘→耶路撒冷, 바울→保罗 | 중국어 성경에 정식 번역어 존재, LLM이 100% 정확 |
| 보편적 신학 개념 | 은혜→恩典, 구원→救赎, 믿음→信心, 회개→悔改 | 양 언어권에서 동일한 개념, LLM이 맥락 이해 |
| 보편적 교회 용어 | 교회→教会, 목사→牧师, 설교→讲道, 찬양→赞美 | 양 언어권 공통, 오역 가능성 제로에 가까움 |
| 문장 구조, 문법 | 전체 문장의 자연스러운 중국어 변환 | LLM의 핵심 능력, 가장 잘하는 일 |

### 번역이 필요할 "수도" 있는 것

| 유형 | 예시 | 실제 문제인가? |
|------|------|----------------|
| 한국 교회 고유 문화어 | 새벽기도회→?, 구역예배→?, 심방→? | 凌晨祷告会, 小组礼拜, 探访 — 중국 기독교인도 대부분 이해함 |
| 한국어 특유 표현 | "은혜 받다"→? (蒙恩), "말씀에 붙잡히다"→? (被话语抓住) | 문맥상 이해 가능, 굳이 시스템화할 정도인가? |
| 교파별 상이한 용어 | 감리교/장로교/성결교 등 교파 용어 차이 | 사용자가 특정 교파의 중국어 표현을 기대하는가? 데이터 없음 |

### 진짜 문제일 수도 있는 것

| 유형 | 구체적 상황 | 심각도 |
|------|-------------|--------|
| **번역 누락** | LLM 응답 중 일부 한국어가 번역되지 않고 그대로 출력됨 | 중간 — 드물게 발생, 재요청하면 해결 |
| **문체 부자연** | 직역투, 어색한 중국어 문장 | 낮음 — 이해는 됨 |
| **신학적 뉘앙스 손실** | 한국어 설교의 감정적/영적 뉘앙스가 중국어에서 약화됨 | 불명 — 측정된 바 없음 |

## 3. 핵심 질문: 지금 당장 무언가를 만들어야 하는가?

### 현재 이미 갖춰진 것

```
사용자 → target_lang="zh" → LLM이 한국어 응답 생성 후 중국어로 출력
                              ↑
                         이미 충분히 작동 중
```

- API 파라미터 하나로 중국어 응답 실시간 제공
- Enhanced RAG의 `translation.py`로 문서 레벨 번역도 가능
- 추가 코드 0줄

### 현재 부족한 것

| 부족한 것 | 중요도 | 측정 가능 여부 |
|-----------|--------|----------------|
| 중국어 사용자 수 데이터 | **매우 높음** | `target_lang` 파라미터 카운트로 측정 가능 |
| 번역 품질에 대한 사용자 피드백 | **매우 높음** | 불만 접수 채널 없음 |
| 중국어 UI (관리자, 사용자 앱) | 낮음 | 대상 사용자가 있으면 검토 |
| 용어집 | **낮음** — 보편적 용어는 불필요 | — |

## 4. 최종 판단

### 구축하지 않을 것 (과감히 배제)

| 제안 | 배제 이유 |
|------|-----------|
| ✅ 전체 콘텐츠 KO+ZH 이원화 저장 | v1에서 판단. 불필요. |
| ✅ 신학 용어집 기반 번역 통제 | v2에서 판단 후 사용자 피드백으로 확정. 보편적 성경 용어는 번역 시스템 불필요. |
| ✅ 용어 관리 Admin UI | 용어집 자체가 불필요하므로 UI도 불필요. |

### 당장 할 단 한 가지

**`target_lang` 사용량 추적 (30분 공수)**

```sql
-- interaction 테이블에 추가
ALTER TABLE interaction ADD COLUMN target_lang VARCHAR(5) DEFAULT 'ko';
```

```python
# chat.py API에서 저장
interaction = Interaction(
    user_message=msg,
    ai_response=response,
    target_lang=request.target_lang,  # ← 추가
    ...
)
```

이 한 줄이 알려주는 것:
- 중국어 요청이 전체의 몇 %인가? (1%면 논의 종료, 15%면 의미 있음)
- 어떤 시간대/요일에 중국어 요청이 많은가?
- 중국어 사용자는 재방문하는가? (Subscriber 단위 집계)

### 3개월 후 데이터 기반 결정

| 데이터 | 의미 | 액션 |
|--------|------|------|
| `target_lang='zh'` 비율 < 3% | 수요 없음 | 논의 종료, `target_lang` 기능만 유지 |
| 3~10% | 소수 존재 | 번역 시스템 프롬프트 최적화만 (용어집 없이) |
| > 10% | 유의미한 사용자층 | 그때 가서 실사용자 피드백 기반으로 **실제 문제** 해결 |

## 5. 부록: 그래도 불안하다면 — LLM 번역 품질을 올리는 가장 단순한 방법

시스템 구축 없이, **번역 시스템 프롬프트 한 문장 추가**만으로 가능한 것:

```
You are a Korean-to-Chinese translator for Christian theological content.
- Use standard Chinese Bible terminology (和合本)
- Translate naturally as if writing for a Chinese Christian audience
- Preserve theological nuance and emotional tone of the original Korean
- DO NOT leave any Korean text untranslated
- If uncertain about a term, use the most widely accepted Chinese Christian equivalent
```

이 프롬프트 최적화만으로 용어집 없이도 95% 이상의 번역 품질을 확보할 수 있다.

---

## 결론

**보편적 성경 용어는 양 언어권에서 동일한 개념이다. 번역 시스템의 대상이 아니다.**

지금 필요한 것은 시스템 구축이 아니라 **데이터 수집**이다:
1. `interaction.target_lang` 컬럼 추가 (30분)
2. 3개월간 중국어 사용량 추적
3. 데이터가 말해주는 대로 행동할 것

**진짜 문제가 발견되기 전에 해결책을 만들지 않는다.**
