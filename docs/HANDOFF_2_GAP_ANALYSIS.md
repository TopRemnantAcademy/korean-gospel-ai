# 🔍 핸드오프 ② 전체 부족분석 (무엇이 부족한가)

> 대상 모델에게: "한국 1등 종교 AI"가 되려면 지금 무엇이 빠졌는가. 우선순위 순.
> 각 항목은 [현재상태] → [목표] → [구현지시] 형식.

## A. 검색·답변 품질 (최우선)

### A1. Sparse 하이브리드 — 부분완성 ⚠️
- **현재**: 자체 BM25(`sparse_index.py`) 작성됨, retriever 연결됨. 단 **실서버 검증 미완**, 멀티워커 미대응.
- **목표**: dense+sparse RRF로 정확어("렘넌트")·성경장절("요 3:16") recall 95%+.
- **지시**: V1/V2 태스크 완료 검증. `eval_retrieval.py`에 정확어 질의셋 추가해 측정.

### A2. Query Understanding (HyDE) — 미구현 ❌
- **현재**: 사용자 질문을 그대로 임베딩. "힘들어요" 같은 모호 질의 recall 낮음.
- **목표**: `query_service.py` — HyDE(가상답변 생성 후 임베딩) + Kiwi 키워드 추출 + LRU/TTL 캐시.
- **지시**: 설계는 `ENGINE_V2_DESIGN.md §1[A]`. retriever가 이미 `dense_query`/`sparse_query` 파라미터 받도록 준비됨 — chat.py에서 query_service 호출해 넘기면 됨.

### A3. Grounding Verifier (환각·성경인용 검증) — 미구현 ❌ ⭐
- **현재**: LLM이 검색결과 보고 자유 생성. 환각·없는 성경구절 인용 차단 = 사후 정규식뿐.
- **목표**: `grounding_service.py` — 답변 문장이 근거청크에 지지되는지 검증, 성경구절 실재 확인. 종교 AI 신뢰의 핵심.
- **지시**: 설계 `ENGINE_V2_DESIGN.md §2[I]`. 답변 후 백그라운드 검증 → 환각률 측정 지표화.

### A4. Reranker 꺼짐 — 트레이드오프 미해결 ⚠️
- **현재**: 속도 때문에 `RERANKER=none`. top-N 정밀도 낮음.
- **목표**: 조건부 reranker (후보 많을 때만) 또는 서버에서 Cohere/GPU.
- **지시**: `retriever.py`에 "후보 ≤ rerank_top_n이면 reranker 생략" 분기 추가. 서버는 Cohere flag.

### A5. MMR 다양성 — 미구현 ❌
- **현재**: 한 설교 청크가 top-5를 독점할 수 있음.
- **목표**: MMR(λ=0.7)로 의미 다양성 확보.
- **지시**: `retriever.py` 결과 후처리에 MMR 추가.

## B. 데이터·콘텐츠 (1등의 해자)

### B1. 콘텐츠 양 부족 — 치명 ❌
- **현재**: 12개 문서(대부분 테스트/중복). 실제 유효 설교 ~3개.
- **목표**: 수백 편 설교 인덱싱. **콘텐츠가 곧 경쟁력.**
- **지시**: 대량 업로드 파이프라인 안정화 + 배치 인덱싱 스크립트. 중복 자동 감지(이미 dedup_service 있음) 강화.

### B2. 성경 원문 DB 부재 ❌
- **현재**: 설교에 언급된 구절만 있음. "요한복음 3장 전체" 같은 직접 인용 불가.
- **목표**: 성경 66권 전문을 별도 인덱싱 → 설교 + 성경 원문 동시 검색.
- **지시**: 공개 성경 텍스트(개역개정 등 저작권 확인) 별도 컬렉션. 답변 시 성경 직접 인용 가능.

### B3. Q&A·요약 생성 (INGEST Stage 6) — 미구현 ❌
- **현재**: 청크만 인덱싱. 가상질문 인덱싱(역HyDE) 없음.
- **목표**: 섹션별 요약 + Q&A쌍 생성 → recall↑, 미리보기 품질↑.
- **지시**: `ingest_pipeline.py`에 Stage 6 추가. 설계 `INGEST_PIPELINE_DESIGN.md`.

## C. 상담 깊이 (차별화 ②)

### C1. 대화 메모리 얕음 ⚠️
- **현재**: 최근 3턴만 prepend (`memory_service`).
- **목표**: 장기 기억 — 사용자의 영적 여정·반복 고민을 요약 저장하고 재방문 시 활용.
- **지시**: 세션 요약을 subscriber 프로필에 누적. 이미 `salvation_status` 등 필드 있음 — 활용 강화.

### C2. 감정·위기 대응 체계화 ⚠️
- **현재**: safety_service가 자살·중독 키워드만 정규식 차단.
- **목표**: 위기 단계 분류 → 전문기관 연결 + 사역자 알림 + 후속 추적.
- **지시**: classifier의 risk_level 활용해 단계별 프로토콜. 사역자 개입 큐(이미 salvation_detector에 requires_pastor 있음) 실제 알림 연결.

## D. 운영·신뢰성

### D1. Qdrant drift "임시 완화" 미해결 ⚠️
- **현재**: publish_service에 "N2: drift 임시 완화" — DB와 Qdrant 불일치 가능성.
- **목표**: 트랜잭션적 일관성 또는 정합성 검사 + 자동 복구.
- **지시**: 발행 후 DB chunk_count vs Qdrant 실제 포인트 수 검증 job. 불일치 시 재인덱싱.

### D2. 자체 BM25 영속성 없음 ⚠️
- **현재**: 메모리 only. 서버 재시작마다 Qdrant scroll로 재구축(시작 느려짐).
- **목표**: 디스크 캐시 또는 서버모드 BM42 전환.
- **지시**: 서버는 BM42(§핸드오프①). 로컬은 pickle 캐시 옵션.

### D3. 테스트 커버리지 ❌
- **현재**: adversarial 테스트만 있음. 단위 테스트 거의 없음.
- **목표**: 핵심 모듈(chunker/sparse/quality_gate/ingest) 단위 테스트.
- **지시**: 핸드오프③ 참조.

### D4. 관측성 부족 ⚠️
- **현재**: Langfuse 꺼짐. 검색 품질·환각률·응답시간 대시보드 없음.
- **목표**: 운영 지표 상시 측정.
- **지시**: 서버에서 Langfuse 켜고 핵심 지표 추적.
