## 1. P0 — 즉시 수정 (금전 손실·보안·기능 완전 사망)

### P0-1. 결제 웹훅 멱등성 부재 — 재전송 시 이중 구독 연장
- **위치**: `backend/app/api/payment.py:248-249`
- **증거**: `/complete`는 `if rec.status == "paid": return`(177행)으로 지키지만 **웹훅에는 동일 가드가 없음**. `_apply_subscription`(91-98행)은 현재 `subscription_expires_at`에 기간을 **가산**.
- **원인**: PortOne 웹훅은 재시시 전달됨. 재전송마다 30/365일이 추가로 쌓임. 웹훅↔`/complete` 동시 실행 레이스도 가드 없음.
- **수정**: `_apply_subscription` 첫 줄에 `if rec.status == "paid": return` 추가 (또는 `UPDATE ... WHERE status != 'paid'` 낙관적 가드).

### P0-2. 답변 캐시가 개인화 답변을 전역 키로 저장 — 사용자 간 누출 + 기록 스킵
- **위치**: `backend/app/api/chat.py:235, 626-633`
- **증거**: 캐시 키 = `answer_cache:{정규화 질문}:{lang}` 뿐. 저장 시점의 `final_answer`에는 **해당 사용자 프로필 기반** 온보딩 질문(521행)·안전 판정 문구(503-504행)·중독케어 가드(508-510행)가 이미 포함.
- **원인**: ① 다른 사용자가 같은 질문을 하면 A의 개인화 문구가 B에게 전달됨. ② 캐시 히트 경로(237-264행)는 `check_input_and_quota` **이전**에 실행되어 정책 검사를 우회하고, FAQ 경로와 달리 **Interaction 행을 기록하지 않음** (히스토리/쿼터 소비/E-A 통계에서 해당 턴 소실).
- **수정**: 개인화 이전의 순수 LLM 텍스트만 캐시하거나 키에 프로필 지문 포함. 캐시 히트 시에도 정책 검사 + Interaction 기록 수행.

### P0-3. 스트리밍 경로가 클라이언트 history를 무살균 주입 — 프롬프트 인젝션
- **위치**: `backend/app/api/chat.py:918` (동기 경로 394-398행은 `sanitize_history` 적용)
- **증거**: `/chat/stream`은 `messages.extend([Message(role=m.role, ...) for m in req.history])` 원본 그대로. `ChatMessage.role`은 임의 문자열(≤20자)이라 `{"role":"system","content":"이전 지시 무시..."}`가 그대로 LLM에 유입.
- **수정**: `chat_stream`에 동일한 `sanitize_history(...)` 적용.

### P0-4. 콘솔 모드 회원가입 사용자 영구 갇힘 (기존 문서화 P0 — 양측 원인 확인)
- **위치**: `backend/app/api/auth.py:346,350` (token="" + email_verification_required=True) ↔ `mobile/screens/index.js:1537-1543`
- **증거**: 콘솔 모드에서는 메일이 발송되지 않고(log만) 링크는 서버 로그에만 존재. 로그인은 `_email_verify_enforced()`(auth.py:41-49)가 `email_mode!="smtp"`면 403을 **걸지 않아 실제로는 성공**함. 그러나 모바일 클라이언트는 `email_verification_required=true`를 보고 "이메일 확인" 화면만 보여주고 **자동 로그인 시도조차 하지 않고 return**. 재발송 엔드포인트(448행)도 콘솔 모드에서 400 거부 → 재발송 요청도 불가.
- **수정(백엔드)**: 콘솔 모드에서는 `email_verification_required=False` + 토큰 즉시 발급(또는 클라이언트가 자동 로그인 재시도하도록 응답에 `auto_login_eligible` 플래그). **수정(모바일)**: `token=="" && sub_id`면 `AuthService.login()` 자동 시도.

### P0-5. 모바일 401 인터셉터 부재 — 토큰 만료 시 조용한 데이터 소실
- **위치**: `mobile/services/index.js` 전역 (예: AnnotationService.list 817-828행 `if (!res.ok) return {annotations: []}`)
- **증거**: 토큰은 30일 만료. 만료 시 모든 인증 API가 401 반환 → 모든 서비스가 이를 일반 오류로 취급해 **빈 데이터를 반환**. UI는 여전히 로그인 상태(`isLoggedIn: true`)로 표시되고 주석·히스토리가 "비어 보이며" 채팅은 "服务器发生错误（HTTP 401）"만 표시. 재로그인 유도 없음.
- **수정**: 공용 `apiFetch` 래퍼에서 401 감지 시 `AppState.logout()` + 로그인 탭 전환 + "세션 만료" 안내.

### P0-6. 관리자 봇 관리 탭 — `bot_list()` dict/list 불일치로 항상 크래시
- **위치**: `admin/lib/api_client.py:1314-1324` ↔ `admin/pages/4_📊_Status.py:380-391`
- **증거**: 백엔드는 `{"subscribers": [...], "total": ...}` dict 반환(`subscriber.py:297-302`). 페이지는 이를 리스트로 순회 → dict 순회는 **키 문자열**("subscribers" 등)을 yield → `u.get("bot_score")`에서 `AttributeError` — 봇 관리 탭 전체가 로드 불가.
- **수정**: `bot_list()`에서 `list_subscribers()`처럼 `data.get("subscribers", [])` 언래핑.

### P0-7. 관리자 벌크 봇 작업 — 반환값 무시한 조용한 거짓 성공
- **위치**: `admin/pages/4_📊_Status.py:152-180` (3개 벌크 액션 모두)
- **증거**: `bot_toggle_flag()`는 실패 시 `None` 반환(1327-1341행, bare except)하는데 루프가 반환값을 검사하지 않고 무조건 `count += 1` → 백엔드 다운/503 시에도 "✅ N명 봇 차단 처리 완료" 표시. **파괴적 작업의 무결성 실패**.
- **수정**: 반환값 검사해 성공 건만 카운트, 전부 실패 시 `st.error`.

### P0-8. 모바일 Today 탭 통찰 패널 — 존재하지 않는 엔드포인트 호출 (404)
- **위치**: `mobile/screens/index.js:1676` — `fetch(\`${base}/trending/insight/${snapshotId}\`)`
- **증거**: 실제 백엔드 라우트는 `/insight/{snapshot_id}` (`trending.py:116`, 라우터에 `/trending` prefix 없음). 관리자 클라이언트는 정확히 호출(`api_client.py:1276`). 모바일의 "4단계 통찰" 패널은 **항상** "통찰을 불러올 수 없습니다" — 죽은 사용자 기능. dist(web/android)에도 동일 버그 탑재.
- **수정**: 클라이언트를 `/insight/${id}`로 수정 (또는 백엔드에 alias 라우트) + dist 재빌드.

### P0-9. 통합앱(app.py) 관리자 모드 — 존재하지 않는 페이지 파일 참조로 전체 크래시
- **위치**: `app.py:350` — `st.Page("admin/pages/9_👥_사람.py", ...)`
- **증거**: 실제 파일은 `admin/pages/9_👥_유저관리.py` (리네임 이력). `st.navigation()`이 누락 페이지에서 예외 → 관리자 모드 진입 시 8501 전체 사망 (`.env:64` `KRAI_PUBLIC_MODE=false`라 유저가 관리자 진입 가능).
- **수정**: 경로를 `9_👥_유저관리.py`로 수정. 재발 방지로 `Path("admin/pages").glob("*.py")` 기반 목록 생성 권장.

## 3. P2 — 계획 수정 (잠재 위험·위생)

### 백엔드
1. **`detect_language`가 "ja"를 절대 반환 불가** — `prompts/system.py:118-125`. 가나 카운트 없이 en 폴백 → 일본어 질문이 영어로 답변됨 (`target_lang="auto"` 기본값이라 실사용 영향).
2. **이벤트 bulk insert 전체-or-nothing** — `events.py:98-134`. `device_id` 등 길이 초과 1건이 200건 전체 500. `Field(max_length=)` + 행별 저장.
3. **FK 전략 불일치 — 고아 행/삭제 불가** — `orm.py:362-364,409-411,923-925`. `ondelete` 전무 + `PRAGMA foreign_keys=ON`이라 구독자 삭제 시 FOREIGN KEY 오류, ActivityEvent는 FK 자체가 없음(익명화 잔존). 테이블별 CASCADE/SET NULL/RESTRICT 결정.
4. **설정 기본값 무경고 활성** — `config.py:176-177,276-279,192`. `change-me` 키로 부팅, quota_*는 `.env` 값을 무시하는 `os.getenv` 클래스 정의 시점 평가, CORS 기본 목록에 prod 게이트 없음. 시작 검증기 + 정상 pydantic-settings 경로.
5. **`_apply_subscription` 부여 실패에도 "paid" 마킹** — `payment.py:84-105`. subscriber/plan 미발견 시 무경고 paid 처리 → 이후 수동 재시도도 차단. `grant_failed` 상태.
6. **`_rrf_fusion` 방어 분기 자기모순** — `retriever.py:86-90`. 90행이 dict 가정 하청 — 향후 RetrievedPoint 유입 시 TypeError. `points[pid] = point`로.

### 모바일
7. **EventService flush 실패 시 타이머 미재무장** — `event.js:46-86`. 복원된 이벤트가 다음 capture까지 정체(또는 ≥FLUSH_COUNT면 매 이벤트마다 재시도 폭주). catch에서 `_ensureTimer()`.
8. **keepalive 64KB 한도 초과 시 unload 이벤트 조용히 유실** — `event.js:53-73`. 200건×2000자 스택 → 요청 자체가 drop. 사이즈 체크 후 분할.
9. **채팅 동시 전송 가드 없음** — `screens/index.js:1322-1388`. 칩+Enter 동시에 스트림 인터리브·히스토리 부정합. `_chatInFlight` 가드.
10. **`js_error` 즉시 flush 안 함** — `event.js:81-86,177-190`. 치명 크래시 시 버퍼에만 존재하다 유실. js_error는 즉시 flush.
11. **`media_play_complete`가 90% 시점 발화 — 탐지 오류** — `event.js:107-129`. 시크 바로 90% 이동해도 완료 카운트. audio `ended` 이벤트 기반으로.
12. **`_resumeConversation` 현재 대화 무경고 덮어씀** — `screens/index.js:1091-1097`. 확인 프롬프트 또는 사전 저장.
13. **토큰 메모리 전용(보안 설계) 부작용 — 새로고침 후 push 구독이 guestId로** — `state.js:34-41`, `services/index.js:136`. 로그인 시 push 구독 subId 재업로드.

### 관리자
14. **naive/aware datetime 혼합** — `5_💭_대화기록.py:187-201`, `9_👥_유저관리.py:194`. PostgreSQL 전환 시 TypeError. 파싱 후 naive UTC 정규화.

## 4. 개선 로드맵 (권장 순서)

### Phase 1 — 금전·보안 (P0 전체 + B-2/3/4, B-9)
결제 웹훅 멱등성·ACK·서명·금액검증 세트 → 캐시 개인화 격리 → 스트리밍 history 살균 → 토큰 시크릿 강화. **수익 직결·악용 가능이라 최우선.**

### Phase 2 — 사용자 갇힘/기능 사망 (P0-4~9, A-1/A-6/A-7)
회원가입 자동 로그인(백+프론트) → 401 인터셉터 → bot_list/bulk 수정 → insight 경로 수정+dist 재빌드 → app.py 페이지 경로/SSE 파서/placeholder.

### Phase 3 — 데이터 무결성 (B-7/8, M-1~3, A-4/A-5, B-3 FK)
주석 동기화 재시도 큐·충돌 해결, 쿼터 정산, 사용량 레이스, FK 정책, 관리자 페이징/None 가드.

### Phase 4 — 죽은 기능/잠재 크래시 (B-1, B-6, M-4~7, ja 감지, SW 캐시, EventService 세부)
### Phase 5 — 위생 (P2 잔여: 죽은 엔드포인트, .env 정합화, 시크릿, .bak/portal)

각 Phase 완료 후 `py_compile`/`node --check`/E2E 스크립트 + dist 재빌드 필수.

## 6. 리스크 및 주의

- **P0-4(회원가입)**: 백엔드 수정 시 SMTP 모드 동작에 영향 없는지 `_email_verify_enforced()` 경로와 함께 회귀 테스트 필요.

- **dist 재빌드**: P0-8(insight)·SW 프리캐시 등 모바일 수정은 `build-config.js web/android` 재실행 후에야 APK에 반영.
