## 2. 🔴 치명: 한국어 문장 분리기 단어 조각화 (수정 완료)

**위치**: `backend/app/services/chunker.py` `_SENT_SPLIT_RE`

**증상** (실제 실행 결과):
```
입력: 저는 다락방 회원입니다 오늘 말씀은 요한복음 3장입니다
출력: ['저는 다', '락방 회원입니', '다', '.', '오늘 말씀은 요', '한복음 3장입니', '다', '.']
```
`다락방`→`다 락방`, `요한복음`→`요 한복음`, `이름`→`이 름` 등 **단어 중간이 음절 단위로 쪼개짐**.

**원인**: `(?<=[다까죠네라요이며름수겠군께십니까다요])\s*` — 문자 클래스에 단일 음절(다/요/름/수/니…)을 나열하고, `\s*`가 **공백 0개에도 매칭**되어 "어미 뒤"가 아니라 "해당 음절이 나오는 모든 위치"에서 분리. `다`는 "다락방", `요`는 "요한복음", `름`은 "이름" 안에서도 등장하므로 광범위하게 오분할.

**영향**: 조각난 텍스트로 dense 임베딩·BM25·LLM 컨텍스트가 전부 오염 → 검색 정확도 근본 저하.

**수정**: 단일 음절 lookbehind를 **전체 종결어미 패턴 + `(?=\s+[가-힣A-Za-z0-9(])` lookahead**로 교체. `re.split` 캡처 그룹으로 종결어미를 앞 문장에 재부착해 어미를 보존. (Python 표준 `re`는 가변길이 lookbehind 미지원이므로 그룹 재부착 방식 채택)

**검증 결과**:
```
입력: 저는 다락방 회원입니다 오늘 말씀은 요한복음 3장입니다 여러분 이 진리를 기억하세요
출력: ['저는 다락방 회원입니다.', '오늘 말씀은 요한복음 3장입니다.', '여러분 이 진리를 기억하세요']  ✅
```

## 3. 🟡 enhanced_rag 청킹 설정 오적용 (수정 완료)

**위치**: `backend/app/services/enhanced_rag/chunking.py` `_chunk_recursive`

**문제**: `_ko_chunk_text(text, target_tokens=350, chunk_size=500, chunk_overlap=80)` 호출.
1. `chunker.chunk_text`의 하위호환 분기(`if chunk_size is not None: target = estimate_tokens("x"*chunk_size)`)가 `target_tokens=350`을 **~275로 덮어씀**.
2. `chunk_overlap` 파라미터는 `chunk_text`가 **전혀 읽지 않아 무시됨** (실제 오버랩은 `overlap_sentences=1` 기본값).

**수정**: `max_tokens`/`min_tokens`/`overlap_sentences`를 `settings.ingest_*`에서 명시 전달. 검증: target 350 유지, 오버랩 2문장 적용.

## 8. 청크 포맷 현황 (정의 확인)

저장 payload(`publish_service.py`)는 다음 필드로 잘 정의됨:
`doc_id / doc_key / version_id / version_number / title / doc_type / series / scripture_refs / topic_tags / chunk_seq / is_canonical_doc / section_title / token_estimate / context_prefix / target_salvation_stage / darakbang_tier / salvation_focus_score / gospel_core_tag` + `text`(본문).

- 벡터는 `embed_texts`(맥락 강화 포함)로, 표시 텍스트는 `chunk.text`(원문)로 저장 — Anthropic식 contextual retrieval 패턴(정상).
- 참고: `context_prefix`는 임베딩에만 쓰이고 LLM 프롬프트에는 주입되지 않음(의도된 설계). `title`/`section_title`도 컨텍스트 텍스트에 병기되지 않아, 필요 시 `build_prompts`에서 `[제목/섹션] + 본문`으로 병기하면 답변 품질 개선 여지 있음.

## 9. 설정 최적화 평가 (요청 3번)

| 항목 | 현재값 | 평가 |
|------|--------|------|
| `ingest_chunk_target_tokens` | 350 | 적정 (KURE 512 한도 내) |
| `ingest_chunk_max_tokens` | 512 | 적정 (임베더 한도 일치) |
| `ingest_chunk_min_tokens` | 50 | 적정 (부스러기 병합) |
| `ingest_chunk_overlap` | 2 (문장) | 적정 (이제 전 경로 일관 적용) |
| `retrieval_top_k` / `rerank_top_n` | 20 / 5 | 적정 |
| `recall_k` 동적 | `max(top_k*3, 80)` | 적정 (지연 최적화됨) |
| `context_top_k` / `context_max_tokens` | 3 / 900 | 공격적(LLM 컨텍스트 3청크·3문장 제한) — 의도된 토큰 예산 |
