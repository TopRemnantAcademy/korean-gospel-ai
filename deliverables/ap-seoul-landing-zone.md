# AI Gospel (korean-gospel-ai) → 腾讯云韩国首尔 (ap-seoul) 着陆区设计
> 角色：Landing Zone 专家（landing-zone-expert）
> 范围：账号体系、VPC 网络拓扑、安全基线、PIPA 合规与数据保护、成本与待验证项、交付架构师的约束清单。
> 说明：本环境无法调用 MigraQ，以下基于腾讯云标准知识给出；**所有「⚠️待复核（控制台/MigraQ）」项需二次确认**。本文件只做着陆区/网络/安全基线，不展开应用层 HA/DR（属对口架构师）。

## 0. 设计前提与约定

| 项 | 取值 / 假设 |
|----|------------|
| 项目形态 | 单项目、单业务（korean-gospel-ai），采用**单主账号 + 单 VPC 单环境**着陆区（非多账号多 VPC）。生产/测试如需隔离，建议用同主账号下**独立 VPC 或独立子网 + 标签**隔离（见 §1）。 |
| 区域 | `ap-seoul`（首尔），假设 **2–3 个 AZ**：`ap-seoul-1` / `ap-seoul-2` / `ap-seoul-3` |
| 部署形态 | 先 **CVM + Docker Compose + CLB** 快速上线，后续演进 **TKE**；本着陆区同时兼容两种形态（子网/安全组/路由不冲突）。 |
| 数据驻留 | 所有有状态资源（VPC、CVM/TKE、TencentDB、COS 桶、Redis、KMS 密钥）均落在 `ap-seoul`，满足 PIPA 数据驻留诉求。 |
| 网络边界 | **仅 CLB 暴露公网**；后端、Qdrant、DB、Redis 全部在私有子网；出站公网统一走 **NAT 网关**。 |

## 1. 账号与权限策略

### 1.1 账号模型（单项目场景）

> 单项目不必上"多账号组织（Organization）"重武器，但应坚持 **主账号与日常运维隔离 + 子账号/角色最小权限**。

```
主账号 (Root / 企业实名)
 ├─ 仅用于：计费、发票、CAM 最高管理、密钥恢复(break-glass)
 ├─ 禁止：日常登录、运行服务、放访问密钥(AK/SK)
 │
 ├─ 子账号 / CAM 角色
 │   ├─ ops-deploy   (运维/部署)    → 管理 CVM/TKE/CLB/NAT/COS/镜像仓库
 │   ├─ db-admin     (数据库管理员) → 仅 TencentDB(PostgreSQL/Redis) 管理，不含计算
 │   ├─ readonly     (只读/审计)    → 只读全部资源 + CLS/监控查看，禁止变更
 │   ├─ cicd-role    (CI/CD)        → 仅推送镜像、触发部署、写 CLS
 │   └─ security-audit (安全审计)   → 仅访问 CloudAudit/CLS 审计日志
 │
 └─ 资源实例角色 (CAM Role / 服务角色)
     ├─ CVM/TKE 节点角色 → 允许访问 COS(备份桶)、CLS(写日志)、KMS(解密)、SSM(读密钥)
     └─ (不使用静态 AK/SK 注入容器)
```

- **主账号 AK/SK**：停用或仅保留一个用于紧急恢复，日常一律用 **子账号 AK/SK** 或 **STS 临时凭证**。
- **资源访问**：CVM/TKE 节点绑定 **CAM 实例角色**，用临时凭证访问 COS/KMS/SSM/CLS，避免密钥落盘。
- **多环境隔离**（如需）：同主账号下 `prod` / `staging` 用独立 VPC（如 `10.0.0.0/16` prod、`10.10.0.0/16` staging）或同 VPC 下独立子网 + `Env=prod/staging` 标签做资源与权限隔离。

### 1.2 角色权限划分（建议策略）

| 角色 | 可执行 | 不可执行 | 认证方式 |
|------|--------|----------|----------|
| ops-deploy | 启停/伸缩 CVM、部署 TKE、管 CLB/NAT、上传 COS、建安全组 | 删主账号、改 CAM 策略、删审计日志 | 子账号 AK/SK + MFA |
| db-admin | 建/备/恢复 TencentDB、Redis、看慢查询/审计 | 碰计算/网络、看应用日志 | 子账号 AK/SK + MFA |
| readonly | 查看全部资源、看监控/CLS | 任何写操作 | 子账号 + MFA |
| cicd-role | 推镜像到 TCR、调用部署 API、写 CLS | 改网络/安全组/DB | CI 流水线用 STS 临时凭证 |
| security-audit | 读 CloudAudit + CLS 审计 | 任何写操作 | 子账号 + MFA |

> 所有子账号强制 **MFA**；CAM 策略遵循 **最小权限 + 显式 Deny 审计日志删除**。

### 1.3 密钥与凭证管理（禁止明文）

- **应用密钥（ADMIN_API_KEY、各类 LLM/嵌入/重排 API KEY、DB 密码、Qdrant api_key）** 全部移入 **SSM（密钥管理 / Secrets Manager）**，运行时由 CVM/TKE 实例角色拉取，**禁止写入 `.env`、镜像层、代码仓库**。
- **DB 凭据**：优先使用 TencentDB 的 **动态凭据 / 托管账号 + 定期轮换**；若不支持则存 SSM 并设轮换计划。
- **镜像**：构建阶段不 `COPY .env`；密钥以 **环境变量/Secret 挂载**（TKE 用 Secret + KMS 加密的 etcd，CVM 用 SSM agent 注入）。
- **凭据轮换**：SSM 中密钥设定期轮换（如 90 天），CLB/API 证书由 SSL 证书服务托管并自动续期。
- **审计**：任何密钥读取、CAM 策略变更均落入 CLS + CloudAudit。

## 2. VPC 网络拓扑

### 2.1 CIDR 规划

| 资源 | CIDR |
|------|------|
| VPC | `10.0.0.0/16`（65,536 地址，预留演进空间） |
| 公有子网 (public) | `10.0.0.0/24` (az1)、`10.0.1.0/24` (az2) |
| 私有-应用子网 (app) | `10.0.10.0/24` (az1)、`10.0.11.0/24` (az2) |
| 私有-数据子网 (data) | `10.0.20.0/24` (az1, master)、`10.0.21.0/24` (az2, standby) |
| 私有-Qdrant 子网 (vector) | `10.0.30.0/24` (az1)、`10.0.31.0/24` (az2) ⚠️或与 app 合并（见 §2.4） |

> 子网掩码 /24（256 地址）足够单环境；如演进 TKE 多节点/多副本，可扩到 /22 或新增子网段。
> 所有 CIDR 落在 RFC1918 私网，不与本地/其他云冲突（本场景无混合云，预留即可）。

### 2.2 拓扑（ASCII）

```
                         Internet (HTTPS :443)
                                │
                        ┌───────▼────────┐
                        │   公网 CLB      │  (internet-facing, SSL 终止)
                        │  FastAPI:8000   │
                        │  Streamlit:8501 │
                        └───┬───────┬─────┘
             健康检查/转发   │       │

        │私有-数据子网│ │私-Qdrant │ │私有-数据 │ │私-Qdrant │

        │ (master)   │ │          │ │ (standby)│ │          │

              │             │            │             │

        ┌─────────────────────────────────────────┐
        │ 公有子网 10.0.0.0/24 (az1)               │
        │   NAT 网关 + EIP (出向)  ←── 私有子网路由 │

        └─────────────────────────────────────────┘
                            │

```

### 2.3 路由表

| 路由表 | 关联子网 | 路由 |
|--------|----------|------|
| RT-Public | 公有子网 `10.0.0.0/24` | `10.0.0.0/16 → local`；`0.0.0.0/0 → IGW` |
| RT-Private-App | 私有-应用 `10.0.10/11.0/24` | `10.0.0.0/16 → local`；`0.0.0.0/0 → NAT 网关`(EIP) |
| RT-Private-Data | 私有-数据 `10.0.20/21.0/24` | `10.0.0.0/16 → local`；`0.0.0.0/0 → NAT 网关`（仅 DB 补丁/备份出网，可更收紧） |
| RT-Private-Vector | 私有-Qdrant `10.0.30/31.0/24` | `10.0.0.0/16 → local`；`0.0.0.0/0 → NAT 网关` |

- **NAT 网关**：放置于公有子网，绑定 **EIP**，统一承载所有私有子网出向流量（LLM/嵌入/重排/Langfuse/包下载/DB 补丁）。
- **CLB**：采用 **公网型 CLB**（自带公网 IP + SSL 终止），后端挂私有-应用子网实例；不要求 CLB「位于」公有子网，但建议将 CLB 后端可用区与私有子网 AZ 对齐。⚠️ 确认 ap-seoul CLB 跨 AZ 分发能力。
- **跨 AZ**：CLB 后端、CVM/TKE 节点、TencentDB 主备、Redis 主从均跨 `ap-seoul-1/2` 分布，单 AZ 故障不影响整体。

### 2.4 层放置决策

| 层 | 子网 | 公网暴露 | 说明 |
|----|------|----------|------|
| CLB（对外） | 公网型（托管） | **是**（仅 :443/:80） | SSL 终止、CORS、健康检查 |
| FastAPI / Streamlit (CVM/TKE) | 私有-应用 | 否 | 仅 CLB 可达；SSH 仅跳板机 |
| Qdrant（自托管 server） | 私有-应用 **或** 独立私有-Vector | 否 | 与后端同 AZ 低延迟；内存型实例优先 |
| TencentDB PostgreSQL | 私有-数据 | 否 | 主备跨 AZ，内网 5432 |
| TencentDB Redis | 私有-数据 | 否 | 主从跨 AZ，内网 6379 |
| COS + CDN（PWA 静态） | 托管（首尔桶） | 经 CDN | 不走 VPC，独立出网 |
| NAT / EIP / 跳板机 | 公有 | NAT 出向；跳板 :22 受限 | 运维入口 |

## 3. 安全基线

### 3.1 安全组（最小权限，按层）

> 原则：默认拒绝；仅放行业务必需端口；跨层用**安全组互信**（源写对端 SG-ID），不写 IP。

| 安全组 | 入站规则 | 出战规则 |
|--------|----------|----------|
| **SG-CLB**（CLB 侧/监听器） | `443/tcp ← 0.0.0.0/0`；`80/tcp ← 0.0.0.0/0`（仅用于 ACME/301 跳转） | 放行到 SG-App 的 8000/8501/8502 |
| **SG-App**（FastAPI/Streamlit/Qdrant 节点） | `8000/tcp ← SG-CLB`；`8501,8502/tcp ← SG-CLB`；`6333,6334/tcp ← SG-App`（Qdrant 仅同层）；`22/tcp ← SG-Bastion`（跳板）；`ICMP/健康检查 ← 10.0.0.0/16` | `5432 ← SG-App→SG-Data`；`6379 ← SG-App→SG-Data`；`0.0.0.0/0 → NAT`（出网） |
| **SG-Data**（PostgreSQL/Redis） | `5432/tcp ← SG-App`；`6379/tcp ← SG-App`；**拒绝公网** | 仅 `10.0.0.0/16` 内网；出网收紧（可仅到 NAT 用于补丁） |
| **SG-Qdrant**（若独立 SG） | `6333,6334/tcp ← SG-App`；`6333 ← SG-Qdrant`(副本同步) | 仅内网 |
| **SG-Bastion**（跳板，可选） | `22/tcp ← 企业出口 IP（固定 CIDR，⚠️勿写 0.0.0.0/0）` | 到 SG-App:22 |
| **SG-NAT**（公有子网，NAT 托管） | 由 NAT 服务管理 | — |

### 3.2 网络 ACL（子网级、无状态、纵深防御）

> 安全组为主，NACL 作第二道（无状态，需显式放行往返）。

| 子网 | 入站(允许) | 出站(允许) |
|------|-----------|-----------|
| 公有 | `80,443 ← 0.0.0.0/0`；`22 ← 企业出口CIDR`；`ephemeral(1024-65535) ← 10.0.0.0/16` | `0.0.0.0/0 → 全`；`ephemeral ← 10.0.0.0/16` |
| 私有-应用 | `8000,8501,8502,6333,6334,22 ← 10.0.0.0/16`；`ephemeral ← 0.0.0.0/0(NAT回包)` | `5432,6379 ← 10.0.0.0/16`；`0.0.0.0/0 → 全(经NAT)` |
| 私有-数据 | `5432,6379 ← 10.0.0.0/16`；`ephemeral ← 10.0.0.0/16` | `ephemeral ← 10.0.0.0/16`；`80,443,443 ← 0.0.0.0/0(NAT补丁，可收)` |
| 私有-Vector | `6333,6334 ← 10.0.0.0/16` | 同应用 |

### 3.3 传输 / 静态加密

- **传输加密 (TLS)**：
  - 用户 ↔ CLB：HTTPS（SSL 证书服务签发，PWA/API 全站强制 HTTPS，HSTS）。
  - CLB ↔ 后端：建议 CLB 与后端也走 TLS（或至少内网可信）；Qdrant 启用 `api_key` + TLS（`qdrant_config.yaml`）。
  - 数据库：TencentDB 启用 **SSL 连接**；Redis 启用访问密码/ACL + 传输加密。
- **静态加密 (KMS)**：
  - COS 备份桶 / 静态桶：启用 **SSE-KMS**。
  - TencentDB（PostgreSQL/Redis）：启用 **KMS 存储加密**。
  - Qdrant 节点云硬盘：启用 **云硬盘加密**。
  - SSM 中密钥：底层 KMS 加密。
  - 全部使用 **ap-seoul 地域 KMS 密钥**，密钥策略限定仅本项目角色可用。

### 3.4 日志与审计

- **CLS（日志服务）**：收集 CVM/TKE 容器日志、Qdrant/后端应用日志、CLB 访问日志、后台 ingest 失败告警。
- **CloudAudit（操作审计）**：所有 CAM/资源变更、密钥读取、安全组变更留存（**禁止子账号删审计**）。
- **DB 审计**：TencentDB 慢查询 + SQL 审计开启。
- **告警**：CLB 5xx、CVM CPU/内存、DB 连接数、Qdrant 内存、NAT 出流量突增、ingest 失败。

### 3.5 WAF / CC 防护（对外 PWA + API）

- 在 **CLB 前挂 WAF**（SaaS WAF / CLB 型 WAF），覆盖 PWA 与 FastAPI API：
  - 防 SQL 注入 / XSS / 命令注入（尤其 `/admin/*`、`/chat` 接口）。
  - **CC 防护 / 速率限制**：对 `/chat`、`/suggestions` 做每 IP/QPS 限流；配合应用层 `RATE_LIMIT_ENABLED`。
  - Bot 管理、地域封禁（如非业务地区）。
  - API 侧额外：身份校验（`Authorization: Bearer`）、输入校验、Admin 接口仅限内网或强 MFA + IP 白名单。
- ⚠️ 确认 ap-seoul WAF 是否支持所需规则模板与 API 防护粒度。

## 4. 合规与数据保护（韩国 PIPA 落地）

> 用户称无特殊要求，但项目处理 **users / subscribers** 个人数据，PIPA 仍可能适用。建议按下表落地，降低合规风险。

| PIPA 维度 | 落地项 |
|-----------|--------|
| **数据驻留** | 所有有状态资源位于 `ap-seoul`（VPC、CVM/TKE、TencentDB、COS 首尔桶、Redis、KMS 密钥均 ap-seoul）。⚠️确认 COS 首尔桶、KMS ap-seoul 密钥可用。 |
| **传输/存储加密** | 全站 HTTPS(TLS) + KMS 静态加密（见 §3.3）。个人信息字段（如 subscriber 联系方式）建议应用层额外加密。 |
| **访问审计** | CLS + CloudAudit 记录所有对个人数据的访问/变更；DB SQL 审计开启；按需可追溯。 |
| **最小权限** | CAM 角色最小权限（§1）；DB 按业务账号分权，禁止应用直连超级账号。 |
| **个人信息最小化** | 仅收集业务必需字段；`users/subscribers` 表审计字段用途；非必要不存明文敏感信息。 |
| **保留与删除** | 制定备份保留策略（如 30/90 天）与个人信息删除/撤回同意机制（用户撤回时清理/匿名化）。 |
| **DPIA 建议** | 若确属 PIPA 适用（收集韩国居民个人信息），建议在上线前完成 **数据保护影响评估 (DPIA)**，记录数据类型、用途、跨境/出网依赖（LLM/嵌入/重排/Langfuse 是否出境）、风险与缓解。 |
| **出境注意** | 调用 LLM/嵌入/重排/Langfuse 经 NAT 出公网，**⚠️需确认这些 SaaS 是否将韩国用户数据传出境外**——若涉及，PIPA 跨境传输条款可能触发，建议优先使用**同地域/韩国可达**端点或本地推理。 |

> 交付清单：建议产品/法务确认「是否实际收集韩国居民个人信息 + 留存期限 + 同意撤回流程」，再定 DPIA 深度。

## 5. 成本与待验证项

### 5.1 主要成本驱动
- **NAT 出流量**：LLM/嵌入/重排/Langfuse 出站按流量计费，是**主要变动成本**。建议：① 评估嵌入/重排改本地推理（CVM 计算型/可选 GPU）省 NAT 流量；② LLM 端点若支持 ap-seoul 私有网络接入则降本并降延迟。
- **CVM/TKE 实例**：S5/M5 按需或包年包月（长期用包月更省）。
- **TencentDB**：双节点跨 AZ 主备按规格计费；Redis 主从。
- **CLB + CDN + COS + WAF + KMS + CLS**：相对小头，但 WAF/CDN 流量按量。
- **COS 标准存储 + CDN 流量**：PWA 静态，量小。

### 5.2 ⚠️待复核（控制台 / MigraQ）
1. **ap-seoul AZ 实际数量与命名**（假设 2–3 个）。
2. **CVM 在售实例族**（S5/M5/C6/SA2）与库存。
3. **TencentDB for PostgreSQL/MySQL** 版本（15/16）、HA 主备跨 AZ 架构；**Redis** 标准/集群架构。
4. **腾讯云 VectorDB 是否在 ap-seoul 可用 + 是否提供 Qdrant 兼容 API**（决定向量库走自托管还是托管）。
5. **大模型 API（DeepSeek/混元）端点**：能否从 ap-seoul 直接调用、延迟、配额、是否支持私有网络接入。
6. **SSM / KMS / CLS / CAM / 云监控 / WAF** 在 ap-seoul 的可用性与功能粒度。
7. **COS 首尔桶多 AZ 开关、CDN 韩国加速节点、自定义域名与 HTTPS**。
8. **CLB 跨 AZ 分发、NAT 网关规格与计费单价**。
9. **LLM/嵌入/重排/Langfuse 是否跨境传输**（PIPA 出境影响）。
10. **嵌入(KURE)/重排(bge_m3) 本地推理 vs 托管 API**（决定 CVM 规格与 NAT 成本）。

## 6. 输出给架构师的约束清单（落地应用架构用）

> 架构师在其上落 FastAPI/Streamlit/Qdrant/DB 应用架构时，须遵守以下硬约束。

**VPC / 网络**
- VPC CIDR：`10.0.0.0/16`，区域 `ap-seoul`。
- 公有子网：`10.0.0.0/24`(az1)、`10.0.1.0/24`(az2) — 放 NAT、跳板。
- 私有-应用：`10.0.10.0/24`(az1)、`10.0.11.0/24`(az2) — 放 FastAPI/Streamlit/Qdrant 节点。
- 私有-数据：`10.0.20.0/24`(az1,master)、`10.0.21.0/24`(az2,standby) — 放 PostgreSQL/Redis。
- 私有-Vector（可选独立）：`10.0.30.0/24`(az1)、`10.0.31.0/24`(az2)；或并入应用子网。
- 路由：私有子网 `0.0.0.0/0 → NAT`；公有子网 `→ IGW`。
- 跨 AZ：CLB 后端、CVM/TKE、DB 主备、Redis 主从跨 az1/az2。

**对外暴露**
- 唯一公网入口：**公网 CLB（:443/:80，SSL 终止）** → 后端 `:8000`、UI `:8501`、管理 UI `:8502`。
- 禁止任何 CVM/DB/Qdrant 直接绑定公网 IP。

**安全组端口（最小）**
- CLB：`443`/`80`（入 0.0.0.0/0）→ 转发 `8000/8501/8502` 到 SG-App。
- App：`8000/8501/8502` 仅来自 SG-CLB；`6333/6334` 仅来自 SG-App；`22` 仅来自 SG-Bastion；健康检查来自 `10.0.0.0/16`。
- Data：`5432` 仅来自 SG-App；`6379` 仅来自 SG-App；**拒绝公网**。
- Vector：`6333/6334` 仅来自 SG-App。

**密钥 / 加密**
- 所有密钥入 **SSM**，容器经 **CAM 实例角色** 拉取，禁止 `.env`/镜像明文。
- 全站 **HTTPS(TLS)** + **KMS 静态加密**（COS/DB/云盘/SSM），KMS 密钥限 ap-seoul。

**合规**
- 有状态资源全部 ap-seoul；启用 CLS + CloudAudit + DB 审计；个人信息最小化与保留策略；上线前按需 DPIA；评估出站 SaaS 是否跨境。

**运维**
- 日志统一 CLS；告警覆盖 CLB 5xx、CVM/DB/Qdrant 指标、NAT 出流量、ingest 失败。
- 后台 ingest 常驻执行体：CVM 用 systemd/supervisor，TKE 用 Deployment/CronJob/Job。
