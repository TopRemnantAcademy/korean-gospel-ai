# 비합리적 설정 점검 리포트

> 관점: "다른 제품들은 표준으로 잘 쓰는데, 우리 설정만 어긋나 있거나 비합리적인 것"
> 대상: `.env`(실제 런타임 설정) + `config.py` 기본값 + 관련 코드. 파일·라인 근거.

---

## 🔴 치명 — 기능이 지금 중단되어 있는 설정

### 1. 결제 채널키 미설정 → 결제가 통째로 실패
- **위치**: `.env` `PORTONE_CHANNEL_KEY=`(비어 있음) ↔ `backend/app/api/payment.py:122-126`
- **증상**: `PORTONE_STORE_ID`·`PORTONE_API_SECRET`은 정상 값이 들어있는데 **채널키만 비어** 있어, 결제 준비(`/api/payment/prepare`)가 **503 "PORTONE_CHANNEL_KEY가 설정되지 않았습니다"** 를 즉시 반환. → 사용자가 결제 버튼을 눌러도 결제창 자체가 열리지 않음.
- **비합리성**: PortOne 연동은 대부분 완료해 놓고(스토어ID+시크릿) 마지막 채널키 하나만 빠져 있어, 정상처럼 보이지만 실제로는 결제가 0건 성공. `config.py:182` 주석도 "미설정 시 결제 생성 실패"라고 명시.
- **조치**: PortOne 콘솔에서 채널 키 발급 → `.env` `PORTONE_CHANNEL_KEY` 설정.

### 2. 결제 웹훅 서명 검증 생략
- **위치**: `.env` `PORTONE_WEBHOOK_SECRET=`(비어 있음)
- **증상**: `config.py:187` "설정 시 HMAC-SHA256 검증" — 비어 있으면 검증을 생략 → **위조 결제완료 웹훅을 검증 없이 수용**할 수 있음(승급 사기 위험).
- **조치**: PortOne 콘솔에 등록한 웹훅 시크릿을 `.env`에 설정.

## 🟠 높음 — 설정 간 모순·혼란

### 3. LLM 주 모델이 설정 두 곳에서 서로 다르게 지정됨
- **위치**: `.env` `LLM_PROVIDER=tencent`(78초 reasoning 모델) ↔ `LLM_FALLBACK_CHAIN=nvidia,tencent,gemini`(nvidia가 첫 번째, TTFT 0.48초)
- **증상**: `.env` 안에 **서로 상충하는 주석 2개**가 공존 —
  - 3~7줄: "tencent 실패 시 nvidia" (tencent 우선)
  - 8줄: "nvidia(주, 실측 TTFT 0.48s로 최고속) → tencent → gemini" (nvidia 우선)
- **원인/비합리성**: `backend/app/services/llm/fallback.py:75-98` `resolve_fallback_chain()` 은 `LLM_FALLBACK_CHAIN`이 설정되어 있으면 **`LLM_PROVIDER`(및 호출자가 넘긴 `primary_provider`)를 완전히 무시**한다. 즉:
  - 채팅(`chat_with_fallback`)은 nvidia 우선으로 동작(실제로는 빠름)
  - `get_llm()`(factory, `config.py llm_provider` 사용)은 tencent로 동작
  - → **경로에 따라 0.48초 모델과 78초 모델이 섞여서** 주 모델이 뭔지 혼란. `LLM_PROVIDER=tencent`는 사실상 거짓 설정.
- **조치**: `LLM_PROVIDER`를 `nvidia`로 정정하거나, `LLM_FALLBACK_CHAIN`을 `tencent,nvidia,gemini`로 바꿔 **양쪽 일치**시키고 주석 정리. (권장: 지연 관점에서 nvidia 우선)

### 4. 임베더 목록과 다국어 라우팅 불일치
- **위치**: `.env` `EMBEDDER_LIST=kure`(kure만) ↔ `backend/app/api/chat_pipeline.py:694-705` `_route_embedder()` 가 비한국어(zh/en) 쿼리를 **`bge_m3`로 하드코딩 라우팅**
- **증상**: `EMBEDDER_LIST`에 `bge_m3`가 없는데도 비한국어 질의는 bge_m3 로드 시도 → 실패 시 KURE로 폴백(`chat_pipeline.py:314-327`). 동작은 하지만 "목록에 없는 임베더를 항상 시도 후 폴백"하는 낭비 구조.
- **조치**: `EMBEDDER_LIST`에 `bge_m3` 추가하거나, `_route_embedder`가 `settings.embedders`를 참조하도록 정합.

## 🟡 보통 — 프로덕션에선 비합리적인 설정

### 5. API 문서 노출 (`DOCS_ENABLED=true`)
- **위치**: `.env` `DOCS_ENABLED=true` ↔ `backend/app/main.py:231-234` (false 시 /docs·/openapi 차단)
- **비합리성**: 주석에도 "운영/공개 배포에서는 false"라 명시했는데 true로 켜져 있어 **Swagger·OpenAPI 스키마가 공개 노출**. 공격면 확대.
- **조치**: 배포 환경에서 `DOCS_ENABLED=false`.

### 6. Google 로그인 비활성인데 UI엔 버튼 노출
- **위치**: `.env` `GOOGLE_CLIENT_ID=`(비어 있음 → 로그인 비활성) ↔ `mobile/app.js`의 "Google 登录" 버튼이 무조건 렌더링
- **증상**: 눌러도 항상 "GIS 未加载" 실패하는 죽은 버튼. (APK 점검에서 이미 지적한 항목과 동일)
- **조치**: Google Client ID 미설정 시 버튼 숨김.

### 7. 쿼터 시스템이 두 개로 병존
- **위치**: `token_service.py`(토큰 기반, `token_quota_enabled=False` 기본) ↔ `quota_service.py`(질문 수 기반, 활성, `question_quota` 테이블 + `/quota` 엔드포인트)
- **비합리성**: 목적이 같은 과금/한도 로직이 **두 벌**로 존재. `token_estimate_per_request=2000` 예약 로직은 토큰 쿼터가 꺼져 있어 사실상 미사용. 운영/유지보수 혼란.
- **조치**: 하나로 통일(질문 수 기반 유지 권장)하고 나머지는 제거 또는 명시적 비활성 문서화.

### 8. Langfuse 비활성인데 키는 채워짐
- **위치**: `.env` `LANGFUSE_ENABLED=false` + `LANGFUSE_PUBLIC_KEY`/`SECRET_KEY` 실키 채워짐
- **비합리성**: 꺼져 있는데 자격증명이 평문으로 들어가 있음(혼란 + 불필요한 시크릿 노출면). 사용할 거면 켜고, 아니면 키 제거.

## 🔵 낮음 — 정정 및 소소한 불일치

### 9. [정정] Reranker는 실제로 bge_m3 활성
- 이전 리포트에서 "reranker 기본 none"이라 했던 부분 **정정**: `.env` `RERANKER=bge_m3`가 config 기본값(`none`)을 오버라이드하므로 실제로는 **활성**.
- 단, `reranker.py:101` `RERANKER_MIN_FREE_MEM_BYTES=1.5GB` 가드 때문에 8GB 박스에서 여유 메모리가 부족하면 **조용히 NoOp로 폴백** → 요청 간 재순위 품질이 불안정할 수 있음(로그로 확인 필요).

### 10. max_tokens 이중 값
- `config.py:43` `tencent_max_tokens=1500`(제공자 기본) vs `config.py:148` `chat_max_tokens=700`(채팅 예산). 생성 경로가 어느 값을 쓰는지에 따라 답변 길이가 달라질 수 있는 잠재 불일치.
